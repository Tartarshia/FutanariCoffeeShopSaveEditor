# CoffeeShop 存档编辑器

适用于 Futanari CoffeeShop 的 Windows 本机存档工具。Python 3.10+，运行时只使用标准库；不依赖网络、游戏进程注入或第三方 Python 库。

双击 `启动存档编辑器.cmd` 或运行 `python web_server.py`。浏览器打开本机页面，关闭命令窗口即停止服务；不安装常驻服务。自动查找 Steam 默认目录及 `libraryfolders.vdf` 中的其他游戏库，也可上传 `.sd` 文件到本机。游戏目录可手动指定为包含 `cs.exe` 的文件夹。

## 编辑与查看

| 页面 | 功能 |
| --- | --- |
| 存档分析 | 列出实际数据区、条目数、解压字节占用和含义，包括空数组 |
| 员工与技能 | 每位员工及玩家的基础属性、等级经验、稀有度、好感、工资、工作优先级；员工工作区域与自定义姓名；技能替换、添加、移除、经验及配置效果 |
| 女仆捏人（实验） | 普通女仆的胸部尺寸、发型、耳型、虹膜、高光、纹身与 RGBA 配色；分部位换装与仓库转移、本机真实模型的 WebGL 2 预览及衣装显隐 |
| 店铺 | 资金、H 点、名称、等级经验、近七次评分、难度、剩余融资次数；查看等级对应的基础客流与员工上限 |
| 仓库与物品 | 中文名称与原始 ID、分类、数量、堆叠上限、购入基价与卖价；逐项修改数量、移除或从本机有效目录添加 |
| 菜单 | 当前菜品、食材 ID、剩余份数与单份售价；修改份数与售价 |

名称、技能效果、堆叠上限、等级配置和限制全部读取本机游戏安装目录。不提供随源码分发的游戏资源副本。未知 ID 保留原值；未知游戏规则不开启修改。扩展编辑限于已经核对的游戏代码指纹；游戏更新后版本不匹配将停止扩展字段编辑，提示重新分析。

## 女仆外观与 3D 预览（实验版）

打开存档后选择“女仆捏人”，按女仆切换。胸部尺寸滑块使用游戏保存的 `0–100` 变形权重；发型支持原始 ID 搜索与长短发筛选。耳型、虹膜、眼睛高光和两层纹身来自本机目录。配色提供色板、透明度滑块与精确 RGBA 通道，也可借用另一名女仆的配色或已确认外观。单独撤销目标女仆的外观修改，或通过原有逐项预览保存存档。

3D 预览从本机游戏读取真实身体、发型和当前服装网格及贴图；首次后台建立磁盘索引，后续复用本机缓存。滑动尺寸和调整配色立即更新画面，切换发型/纹身等样式时保留旋转、缩放和观察目标，读取期间旧模型仍可操作。复用浏览器中已经加载的网格与贴图，最近 16 套组合可直接切回；缓存按内存阈值淘汰。拖动模型旋转，滚轮缩放，切换全身、上半身、面部，或保持缩放转向背面。右侧编辑区独立滚动。需要支持 WebGL 2 的浏览器；不使用 CDN、第三方浏览器库或外部模型服务。

模型目前处于静止绑定姿势。胸部和服装分别应用游戏的 `breasts_size` 与 `clothes_breasts_size` 变形；耳型应用对应的三个耳部变形。浏览器着色器近似显示颜色、贴图、阴影与妆容，未复刻 Unity 的完整着色器、动画、骨骼姿态、物理与碰撞。预览用于比较外观，最终以游戏载入效果为准。原存档头像是缓存图片，离线修改不重绘它，游戏中的头像也可能继续显示旧图。

只开放已核对的普通女仆模型。玩家、男性及其他模型保持只读；未找到独立胸型、脸型、身高、腰围的保存字段，因此不提供推测性的滑块。衣装清单现可编辑：按本机有效女装目录筛选部位、搜索名称或 ID，并选择左右配饰。穿上从仓库扣一件，脱下返还一件；替换时先返还占用冲突槽位的整件衣装。也可明确选择“新增一件并穿上”，无需仓库现有数量。数量不足或返还超出堆叠上限时拒绝该次操作，不丢弃物品。

“显示全部”“隐藏外衣”“仅看内衣”和每件服装的显示开关只影响预览，不修改衣装或仓库；多槽位套装按整件显隐。换装同时暂存 `WearingClothes` 和 `/Items`，逐项预览后统一保存并备份。支持撤销最近一次换装及其仓库转移；若仓库又被另行修改，拒绝局部回退，避免覆盖其他编辑。禁止、未知、男性专用衣装不会作为新增选项，原有未知条目保持原样。

长小数输入默认显示最多四位小数，鼠标悬停可查看完整值；未操作的字段仍保留原始字节，不因显示取整而改写。所有模型、贴图、头像、资源索引和私有测试截图只存于 `.local/`，不随源码发布。

## Steam 成就操作

独立的 Steam 成就面板无需打开存档。Windows 下使用 **64 位 Python**，先退出游戏并登录拥有本游戏的 Steam 账号，再点击“读取 / 刷新成就状态”。名称、描述、隐藏标记和解锁时间由 Steam 实时返回，支持搜索、状态筛选和分页。

选择一个未解锁成就 → 查看确认窗口 → “确认解锁此成就”。工具通过本机游戏的 `steam_api64.dll` 调用 `RequestCurrentStats`、`SetAchievement`、`StoreStats`，等待 Steam 提交回调并重新读取状态。操作限定 AppID **3306200** 和 Steam 返回的成就 ID；一次只提交一个成就，没有批量解锁、重置或统计值修改。

成就立即提交至当前登录账号，不能通过撤销存档修改恢复；它与任务领奖和存档导出相互独立。提交失败或超时后先刷新状态，不应把失败提示当作必然未提交。工具不分发 Steam DLL、不需要 Web API 密钥、不上传存档、不记录账号名称或 Steam ID 到源码。原生接口日志可能包含账号标识，仅保留在被忽略的 `.local/` 内。

当前验证覆盖实际 Steam 初始化、63 项成就的只读枚举、页面搜索/筛选/逐项确认，以及模拟接口下的提交回调和回读失败处理。**未主动解锁账号中的真实成就，实际写入链路尚未实测。** Steam 返回的目录数量和状态可能随游戏更新改变。

## 保存与导出

退出游戏并等待云同步 → 打开存档 → 修改 → 查看逐项预览 → 备份并保存原存档。界面覆盖当前打开的 `.sd`，并在同目录创建或更新 `<原文件名>.bak`：它保留本次保存前的完整存档。先验证修改、完整 JSON 和 GZip 回读，再验证备份并原子替换原文件；源文件发生变化时拒绝写入。保存完成后自动重新读取，可继续修改。工具不写游戏安装目录。上传文件保存的是本机上传副本；要直接更新游戏槽位，请打开工具发现的存档或输入原文件路径。

等级修改直接设置等级，不模拟员工随机成长、不自动领取任务奖励。按最终稀有度校验员工等级、经验和技能数；检查技能 ID 和类型冲突；按目标店铺等级检查经验及工作员工人数；仓库数量按本机配置的 `StackLimit` 校验。修改基础属性后实际值仍受技能和临时增益影响。技能的 `Exp` 字段可修改，但目前未发现游戏用它触发技能升级，技能档位由 ID 决定。

恢复备份时先退出游戏，把同目录的 `.sd.bak` 复制回对应的 `.sd`，保留槽位编号。Steam Cloud 可能恢复旧版本；实际载入确认前保留备份。历史记录 `.hs`、游戏设置与游戏安装均未改动。格式校验通过不代表已经在游戏内载入验证。

## 详细报告

`SAVE_FORMAT.md` 是不含私有存档内容的字段及关联说明。也可生成自己的完整私有报告：

```powershell
python analysis.py --source "你的存档.sd" --output ".local/analysis/my-save.md"
```

报告包含逐员工属性与技能、外观/衣装/位置/解锁数据、所有持有物品、由料理书得到的菜谱、当前菜单、地图、扩建、任务、邮件、物价、教程、新标记等；包含当前姓名，须留在本机。报告输出必须是新文件，不覆盖已有报告。

## 实现与验证

GZip → UTF-8 JSON，流式解析与磁盘 SQLite 索引，不构建完整存档对象。长操作在独立进程中完成；普通字段每页 60 项，仓库、地图、目录和任务每页 25 项。头像字节默认隐藏，搜索 `_charaIconByte` 可查看。解压上限 512 MiB，上传上限 128 MiB，允许编辑的小数组最大 256 KiB。

标量修改仅替换对应的 JSON 值；仓库和技能清单的明确增删或替换只重写选中的小数组。其他解压后字节保持一致，原 GZip 压缩字节会变化。导出检查源文件、原始缓存、索引和本机目录缓存的 SHA-256，验证关联、完整 JSON、修改值与 GZip 回读，再原子创建新文件。底层另存导出接口保留；界面保存使用上述备份与覆盖流程。

```powershell
python -m unittest discover -s tests
```

测试使用合成数据，不携带真实存档或提取的游戏目录。开发用反编译与浏览器测试工具只放在忽略的 `.local/` 下，不属于运行依赖。

`.local/` 包含私有存档副本、目录缓存、源路径、分析报告、截图及本机开发工具；`exports/` 包含修改结果。关闭工具后可自行清理这两个目录。不要上传它们。源码发布保留 `LICENSE`、`THIRD_PARTY_NOTICES.md`、`RESEARCH.md` 和 `SAVE_FORMAT.md`。

## 公开版本与打包

从 Releases 下载源码 ZIP，解压到可写文件夹，安装 Python 3.10+（Steam 功能需要 Windows 64 位 Python），双击启动脚本即可。不需安装 pip 依赖。CI 在 Windows / Linux、Python 3.10 / 3.13 上运行合成测试及公开文件审查；Steam 真实账号操作不在 CI 中执行。

在 Git 工作区运行 `python release.py --check` 检查受控文件名单、个人路径、账号标识与常见密钥。运行 `python release.py --output .local/releases/CoffeeShop-source.zip` 生成源码 ZIP。只包含受版本控制的源码、文档和合成测试，不包含游戏 DLL、提取配置、真实存档或个人分析报告。
